# VERSION CONTROL

## Doel

GitHub version control vervangt ongecontroleerde bestandsnaamversies voor operationele documentatie.

## Branching

- Gebruik korte beschrijvende branchnamen: `update-artist-intake-flow`.
- Houd waar mogelijk één conceptuele wijziging per branch.
- Werk gerelateerde documentatie in dezelfde branch bij wanneer een proces verandert.

## Commitstandaard

- Beschrijf wat er operationeel verandert.
- Commit geen vertrouwelijke clientinformatie.
- Commit geen getekende contracten of private commerciële data.

## Reviewcriteria

- De juiste lane owns het proces.
- Toolgrenzen tussen GitHub, Google Drive, ClickUp en Gmail zijn duidelijk.
- SOPs, Workflows en Playbooks spreken elkaar niet tegen.
- De wijziging is uitvoerbaar voor een teamlid dat niet bij het besluit aanwezig was.
