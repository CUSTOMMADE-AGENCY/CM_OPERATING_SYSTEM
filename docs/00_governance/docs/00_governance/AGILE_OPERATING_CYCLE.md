# AGILE OPERATING CYCLE

## DOEL

CM moet niet alleen goed georganiseerd zijn, maar continu blijven verbeteren.

Het OS moet meebewegen met:
- Nieuwe AI tools
- Nieuwe DSP workflows
- Nieuwe music rights modellen
- Nieuwe dealstructuren
- Nieuwe klantbehoeften
- Nieuwe automatiseringsmogelijkheden

## PRINCIPES

- Lean boven complex
- Gebruik boven perfectie
- Data boven gevoel
- Automatiseren waar herhaling zit
- Menselijke controle bij strategie, deals en legal
- Geen tool toevoegen zonder duidelijke ROI
- Geen workflow behouden als niemand hem gebruikt

## WEEKLY OPERATIONS REVIEW

Frequentie:
Wekelijks

Doel:
Kleine fricties snel oplossen.

Check:
- Welke taken blijven liggen?
- Welke templates worden niet gebruikt?
- Waar vraagt iemand steeds opnieuw uitleg?
- Welke ClickUp taken blijven hangen?
- Welke klant/dossier loopt risico?
- Welke actie kan direct worden verbeterd?

Output:
- 3 verbeteracties maximaal
- ClickUp update
- Geen grote systeemwijzigingen

## MONTHLY SYSTEM REVIEW

Frequentie:
Maandelijks

Doel:
Controleren of het OS nog werkt.

Check:
- Welke workflows zijn gebruikt?
- Welke templates zijn gebruikt?
- Welke templates bleven leeg?
- Welke Drive structuur veroorzaakt verwarring?
- Welke ClickUp status klopt niet?
- Welke Gmail template ontbreekt?
- Welke automatisering zou tijd besparen?

Output:
- Template update
- Workflow update
- ClickUp verbetering
- GitHub issue indien governance moet wijzigen

## QUARTERLY TOOL REVIEW

Frequentie:
Per kwartaal

Doel:
Controleren of CM nog de juiste tools gebruikt.

Check:
- Is ClickUp nog beste plek voor execution?
- Is Google Drive structuur nog logisch?
- Zijn er betere AI tools beschikbaar?
- Welke tool kost geld maar levert niets op?
- Welke handmatige taak kan geautomatiseerd worden?
- Welke nieuwe tool kan omzet, tijd of kwaliteit verbeteren?

Tool evaluation criteria:
- ROI
- Tijdsbesparing
- Gebruiksgemak
- Integratie met bestaande stack
- Veiligheid
- Kosten
- Schaalbaarheid

Output:
- Keep / Replace / Remove beslissing per tool
- Automation backlog
- Nieuwe tool alleen testen als er duidelijke use case is

## BI-ANNUAL STRATEGY REVIEW

Frequentie:
Elke 6 maanden

Doel:
Controleren of CM nog op de juiste businessmodellen focust.

Check:
- Welke service levert meeste omzet op?
- Welke service kost te veel tijd?
- Welke klanten zijn winstgevend?
- Welke klanttypes moeten we vermijden?
- Werkt Master Boutique als revenue engine?
- Werkt Artist Management als retainer model?
- Welke diensten moeten worden productized?
- Welke diensten moeten stoppen?

Output:
- Service portfolio update
- Pricing update
- Client criteria update
- Strategic roadmap update

## CHANGE CONTROL

Elke structurele wijziging aan CM OS moet worden vastgelegd.

Gebruik:
- GitHub Issue voor voorstel
- Pull Request voor wijziging
- Versie-update bij grote wijziging

Nooit:
- Losse aanpassingen zonder documentatie
- Duplicaten maken
- Oude workflow laten staan naast nieuwe workflow
- Tool toevoegen zonder eigenaar

## DECISION LOG

Een systeem is alleen goed als het gebruikt wordt.

Als iets niet gebruikt wordt:
- versimpelen
- automatiseren
- verwijderen
