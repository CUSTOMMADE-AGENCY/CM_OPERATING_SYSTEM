# Version Control

## GitHub version control

GitHub tracks the operating-system source of truth. Changes should be committed with clear messages and reviewed through pull requests.

## Document versions

- `V1.0` means first approved operating version.
- `V1.1` means a minor improvement or clarification.
- `V2.0` means a major redesign or lane-level process change.

## Archive rules

Old versions should be moved to the approved archive location in Drive when they are execution documents. Repository documents should remain in Git history rather than duplicated as old files.

## Change discipline

Do not create duplicate documents to preserve old thinking. Use Git history, changelog notes, or Drive archive folders instead.
